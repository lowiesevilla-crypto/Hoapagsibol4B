# PostgreSQL to MySQL Migration Guide

## Completed migration baseline

The application schema now targets MySQL. The previous PostgreSQL migrations remain available in Git history at commit `220542c`; they are intentionally absent from the active MySQL migration directory. The baseline creates 47 MySQL tables with InnoDB-compatible foreign keys, Prisma enums, `utf8mb4`, indexes, and decimal/date types.

The local migration performed on June 30, 2026 followed this protected sequence:

1. Stop application writes.
2. Export every Prisma model from PostgreSQL to ignored JSON.
3. Keep the PostgreSQL container and volume unchanged.
4. Validate and generate the MySQL Prisma client.
5. Create a fresh MySQL 8.4 database.
6. Apply `20260630000000_mysql_baseline`.
7. Import all rows with foreign key checks controlled inside one transaction.
8. Compare every imported model count to the source export.

Verified result: 3,508 total rows imported, including 695 homeowners and 557 bills, with zero count mismatches.

## Repeatable migration procedure

### 1. Freeze writes and back up PostgreSQL

Create both a native `pg_dump` and the provider-neutral application export while running the last PostgreSQL revision:

```bash
pg_dump --format=custom --file=hoa-before-mysql.dump "$DATABASE_URL"
pnpm db:export -- backups/postgres-before-mysql.json
```

Copy uploads and generated documents separately. Record row counts and checksums. Never delete the source database during cutover.

### 2. Deploy the MySQL revision

Set a new MySQL URL and apply the versioned migration:

```env
DATABASE_URL="mysql://hoa_app:STRONG_PASSWORD@MYSQL_HOST:3306/hoa_portal"
```

```bash
pnpm install --frozen-lockfile
pnpm db:generate
pnpm db:migrate:deploy
```

### 3. Import and verify

```bash
pnpm db:import -- backups/postgres-before-mysql.json
pnpm exec prisma migrate status
pnpm typecheck
pnpm build
```

The import command clears the target models, imports the snapshot, and fails if any model count differs. Run it only against the approved target during the cutover window.

### 4. Cut over

Start the new release, check `/api/health`, test login and key financial pages, then direct traffic to MySQL. Keep PostgreSQL read-only until the retention window expires.

## Type mappings

| PostgreSQL concept | MySQL implementation |
| --- | --- |
| Native enum | MySQL enum generated by Prisma |
| `TIMESTAMP(3)` | `DATETIME(3)` |
| `DATE` | `DATE` |
| `NUMERIC(12,2)` | `DECIMAL(12,2)` |
| Unbounded narrative string | `TEXT` |
| JSON/JSONB | MySQL `JSON` |
| Case-insensitive lookup | `utf8mb4_unicode_ci` collation |

## Rollback

Application rollback switches the release symlink with `scripts/rollback-hostinger.sh`. If a forward migration changed data, restore the matching pre-deployment MySQL dump explicitly. The baseline `down.sql` is supplied for disposable/empty environments only; it drops all application tables and must never be run casually in production.
