# Homeowner Account Number Architecture

Date: 2026-07-27
Status: Implemented locally

## Decision

HOAHub now stores a canonical homeowner account number on `HomeownerProfile.accountNumber`.

The account number is:

- exactly 11 digits;
- numeric only;
- not allowed to start with zero;
- globally unique at the database level;
- generated by server-side code;
- not derived from property, block, lot, name, phone, birth date, or other personal data.

Property identifiers remain separate. Block and lot continue to describe the homeowner property; they are not account numbers.

## Canonical Ownership

The canonical owner is `HomeownerProfile`.

Household/family members do not receive separate account numbers unless they have their own homeowner profile. Household-member document requests use the related homeowner account number in request context while snapshotting the household member as the official document subject.

## Non-Reuse

`HomeownerAccountNumberReservation` stores every reserved account number without a cascading foreign key to `HomeownerProfile`. This prevents reuse even if a homeowner profile is later deleted or archived.

`HomeownerProfile.accountNumber` remains unique for fast lookup and display. The reservation table is the historical allocation ledger.

## Migration Strategy

Phase 1 migration:

- add nullable `HomeownerProfile.accountNumber`;
- add unique index on `HomeownerProfile.accountNumber`;
- add `HomeownerAccountNumberReservation`.

Phase 2 backfill:

- run `pnpm exec tsx scripts/backfill-homeowner-account-numbers.ts`;
- preserve already-valid 11-digit account numbers;
- create reservations for preserved values;
- assign missing values;
- log only homeowner IDs and result status.

The field remains nullable in schema so rollout is additive and production-safe. Runtime request submission ensures a missing profile number is generated before new document snapshots are created.

## Application Use

The shared helper `homeownerAccountNumber` returns only a valid canonical number or `UNASSIGNED`. It no longer derives account numbers from block and lot.

`homeownerPropertyLabel` and `legacyHomeownerPropertyAccountReference` preserve the property/reference use case separately.

The document template system exposes `property.accountNumber` for the canonical account number and keeps `property.accountLabel`, `property.block`, and `property.lot` for property data.
